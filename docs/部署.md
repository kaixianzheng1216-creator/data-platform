# 数据中台后端部署指南

## 服务组成

生产 `compose.yml` 包含：

- PostgreSQL：账号和文件元数据。
- Docling：文档解析服务。
- prestart：等待数据库、执行 Alembic、创建首个超级用户。
- backend：FastAPI API。

后端通过 `BACKEND_PORT` 直接映射到宿主机，默认端口为 `8000`。

## 必需配置

部署前从 `.env.example` 创建 `.env`，并替换以下值：

- `PROJECT_NAME`、`BACKEND_PORT`
- `SECRET_KEY`
- `FIRST_SUPERUSER_USERNAME`、`FIRST_SUPERUSER_PASSWORD`
- `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`
- `COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_REGION`、`COS_BUCKET`
- `DOCLING_BASE_URL`，Compose 内默认为 `http://docling:5001`
- `DOCKER_IMAGE_BACKEND`

生成安全密钥：

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

## 首次部署

启动应用：

```bash
docker compose -f compose.yml build
docker compose -f compose.yml up -d
docker compose -f compose.yml ps
```

API 默认位于 `http://<服务器地址>:8000`，Scalar 文档位于 `http://<服务器地址>:8000/scalar`。如修改了 `BACKEND_PORT`，请使用对应端口。生产环境的网络访问控制和 TLS 终止由目标部署平台负责，不包含在本仓库中。

## 数据库兼容性

当前 Alembic revision 是新项目基线，不支持从旧 Agent 数据库原地升级。首次部署应使用空数据库；旧数据必须先备份并通过单独的数据迁移导入。

仓库不使用 GitHub Actions，也不包含自动部署流程。部署前应根据目标平台单独设计镜像发布、密钥管理、网络访问控制和回滚流程。
