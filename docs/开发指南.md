# 数据中台后端开发指南

## 启动服务

从示例创建本地环境文件，至少填写 PostgreSQL、JWT、超级用户和腾讯云 COS 配置：

```bash
cp .env.example .env
docker compose watch
```

Compose 会启动 PostgreSQL、Docling、数据库迁移/初始化任务和 FastAPI。首次启动需要等待镜像下载和 Docling 健康检查。

常用地址：

- API：<http://localhost:8000>
- Scalar：<http://localhost:8000/scalar>

查看日志：

```bash
docker compose logs -f backend
docker compose logs -f docling
```

## 文件上传

文件由客户端直传 COS，不经过 FastAPI 转发：

1. 登录并调用 `POST /api/v1/files`。
2. 使用响应中的 `uploadUrl` 和 `uploadHeaders` 执行 PUT。
3. 调用 `POST /api/v1/files/{file_id}/complete` 完成校验和解析。

当前单文件上限为 100 MiB；纯文本附件和解析结果暂时限制为 256 KiB。后续 RAG 摄取流程应把解析、切块和索引迁移到独立后台任务。

## 数据库迁移

```bash
docker compose exec backend alembic revision --autogenerate -m "Describe change"
docker compose exec backend alembic check
docker compose exec backend alembic upgrade head
```

本次项目清理建立了新的迁移基线，不兼容旧 Agent 数据库。

## 本机后端开发

停止容器内后端后，可以从 `backend/` 直接启动；此时 `.env` 中的 PostgreSQL 和 Docling 地址必须能从宿主机访问：

```bash
docker compose stop backend
cd backend
uv sync
uv run fastapi dev app/main.py
```

## 质量检查

```bash
cd backend
uv run ruff check .
uv run mypy app
uv run ty check app scripts
cd ..
uv run prek run --all-files
```
